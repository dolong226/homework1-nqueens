\section{Background and related work}
\subsection{SAT, cardinality constraints, and the compared models}
SAT asks whether Boolean variables can be assigned so that a formula is
true. In CNF, the formula is a conjunction of clauses, and each clause is
a disjunction of literals. A literal is a variable or its negation. For
example, $(\neg x_1\vee\neg x_2)$ excludes the assignment in which both
inputs are true. If $x_1$ is already true, the remaining literal forces
$x_2$ to be false. This inference is called unit propagation: a clause
with only one unassigned literal and all other literals false forces
that literal to be true. Repeating this rule can detect conflicts without
making another search decision.

For a set of Boolean inputs, ALO requires at least one true input, AMO
allows at most one, and EO requires exactly one. ALO needs a single
disjunction, whereas AMO has several possible CNF representations. Extra
variables can reduce the number of clauses but also change the paths
through which propagation occurs. Thus two encodings with the same
solutions need not take the same time to build or solve.

The models compared here express the same feasibility task using different
variables. SAT and ILP use one occupancy variable per square; the CP model
uses one integer column variable per row. SAT receives clauses, ILP receives
linear equalities and inequalities, and CP receives three global
all-different constraints. These user models are described explicitly in
the following section; their sizes do not describe the internal models
after solver preprocessing.

\subsection{Related work}
\paragraph{N-queens.} Bell and Stevens~\cite{bell} survey the extensive
literature on the puzzle, including explicit constructions that place
$n$ non-attacking queens for every $n\ge4$ in polynomial time. Finding one
placement on an empty board is therefore not a hard decision problem,
but the puzzle remains a common benchmark for constraint models because
its row, column, and diagonal constraints are easy to state and grow
quickly with $n$. Gent et al.~\cite{gent} proved that the completion
variant, in which some queens are fixed in advance, is NP-complete and
that counting its solutions is \#P-complete.

\paragraph{At-most-one encodings.} Prestwich~\cite{prestwich} reviews CNF
encodings of finite-domain and cardinality constraints. The pairwise
encoding needs no auxiliary variables but a quadratic number of clauses.
The binary (bitwise) encoding of Frisch and Peugniez~\cite{frischbinary}
uses a logarithmic number of auxiliaries. Sinz~\cite{sinz} introduced the
sequential counter, whose linear-size AMO case maintains arc consistency
through unit propagation. Klieber and Kwon~\cite{commander} proposed the
commander encoding, which applies AMO hierarchically to groups, and
Chen~\cite{product} the product encoding, which projects inputs onto a
two-dimensional grid. Nguyen and Mai~\cite{nguyenmai} combined the
binary and commander ideas in the bimander encoding. Comparative studies
such as Frisch and Giannaros~\cite{frischamok} report that no encoding is
best across all benchmarks, because formula size and propagation strength
pull in different directions. This motivates measuring the encodings on
the specific problem rather than choosing by clause count.

\paragraph{Exact solvers.} Modern SAT solvers follow the conflict-driven
clause learning (CDCL) scheme introduced by GRASP~\cite{grasp}. The
backends evaluated here are MiniSat~\cite{minisat}, Glucose, which ranks
learned clauses by literal block distance~\cite{glucose},
CaDiCaL~\cite{cadical}, and MapleChrono, which adds chronological
backtracking~\cite{chrono}; all are accessed through PySAT~\cite{pysat}.
In CP, the all-different constraint has a dedicated filtering algorithm
based on bipartite matching~\cite{regin}. CPLEX CP
Optimizer~\cite{cpoptimizer} is a CP engine with automatic search, while
OR-Tools CP-SAT~\cite{cpsat} combines CP propagators with a CDCL SAT core.
Gurobi~\cite{gurobi} and CPLEX~\cite{cplex} solve the ILP model by
LP-based branch and cut.

The five AMO methods above are established constructions, and the course
assignment asks for their implementation and comparison rather than a new
encoding. The contribution of this report is to place all five encodings,
four CDCL backends, and four CP/ILP solvers in one harness with identical
problem semantics, independent solution validation, and a timing breakdown
that separates process startup and license acquisition from model
construction and search.
