\begin{abstract}
This report implements an exact SAT solver for the standard N-queens puzzle
and compares five at-most-one encodings: pairwise, binary, commander, recursive
product, and sequential counter. A minimal formulation and a formulation with
redundant column clauses are evaluated using PySAT. Four SAT backends are
compared using a fixed encoding, followed by comparisons with IBM CPLEX CP
Optimizer, IBM CPLEX MIP, Gurobi, and OR-Tools CP-SAT. The implementation uses
the same problem semantics for every method, independently validates returned
placements, and stores the raw solutions and experiment configurations.
Experiments use fresh processes, one solver thread, three repetitions, and
an enforced ten-second process deadline. Boards up to $512\times512$ are
included to examine scaling. Results distinguish model construction and search
from process startup and license acquisition, and account explicitly for
timeouts. Commander/minimal achieves the lowest encoding PAR-2 (0.450 s).
At $n=512$, CPLEX CP and both MIP baselines succeed in all repetitions,
while reference SAT and CP-SAT reach the deadline.
The study concerns finding one solution to the unconstrained puzzle;
it does not measure counting or the NP-complete completion problem.
\end{abstract}

\section{Introduction}
The N-queens puzzle asks for $n$ queens on an $n\times n$ chessboard such
that no two queens attack each other. It provides a compact example of exact
constraint solving: every row must contain a queen, while columns and
diagonals must exclude conflicts. A Boolean placement model turns these
requirements into cardinality constraints. Its runtime can depend on how
those constraints are translated into conjunctive normal form (CNF), even
when the resulting formulas have exactly the same board solutions.

PySAT supplies a common interface to SAT engines and cardinality
encoders~\cite{pysat}. This makes it possible to compare encoding
choices without changing the application semantics. Constraint programming
(CP) instead represents a queen by its column and expresses non-attacking
conditions with global all-different constraints~\cite{ortools}. Integer
linear programming (ILP) represents occupied squares with binary variables
and linear equalities or inequalities. These alternative formulations allow
a comparison between SAT and established exact solvers.

The present work contributes (i) an executable SAT solver with five AMO
encodings and two formulations, (ii) a semantic verification suite that
checks complete projected solution sets on small boards, (iii) comparisons
with four SAT backends and all four CP/ILP solvers required by the course assignment,
and (iv) reproducible measurements, raw placements, figures, and this report.

The standard puzzle has a solution for $n=1$ and every $n\ge4$, while $n=2$
and $n=3$ are infeasible. Consequently, deciding existence in this particular
family should not be called NP-complete. The N-queens completion problem,
where some queens are fixed in advance, is a different problem and is
NP-complete~\cite{gent}. Here the aim is to study the behavior of generic
exact methods on the standard puzzle, rather than propose a new algorithm
that supersedes explicit constructions.

\section{Problem definition and baseline models}
\subsection{Problem definition}
Let $I=\{0,\ldots,n-1\}$. A placement is a vector $q=(q_0,\ldots,q_{n-1})$
where $q_r\in I$ is the column of the queen in row $r$. It is feasible iff
\begin{align}
q_r&\ne q_s &&\forall r<s,\label{eq:column}\\*
q_r-r&\ne q_s-s &&\forall r<s,\label{eq:down}\\*
q_r+r&\ne q_s+s &&\forall r<s.\label{eq:up}
\end{align}
There is no optimization objective: the first feasible placement suffices.
All models below describe precisely these placements. Figure~\ref{fig:board}
shows a placement returned during the experiments. Rows and columns in the
figure are labeled from one; source code and saved solutions use zero-based
coordinates.

\subsection{Constraint programming}
The CP formulation introduces $n$ integer variables $q_r\in I$ and the three
global constraints
\begin{align}
\operatorname{AllDifferent}(q_0,\ldots,q_{n-1}),\\
\operatorname{AllDifferent}(q_0,q_1+1,\ldots,q_{n-1}+n-1),\\
\operatorname{AllDifferent}(q_0,q_1-1,\ldots,q_{n-1}-(n-1)).
\end{align}
The same expressions are supplied to CPLEX CP Optimizer~\cite{cpoptimizer}
through DOcplex~\cite{ibm} and to OR-Tools CP-SAT~\cite{cpsat}. The counts $n$ variables and three constraints refer to
the user model; solver-internal expansion and presolve may add variables
and constraints. In particular, CP-SAT is not a pure finite-domain CP engine:
it combines SAT-based reasoning with other techniques. Its inclusion provides
an exact baseline through a different modeling interface, rather than a
disjoint category of algorithms.

\subsection{Binary ILP formulation}
Define $x_{rc}\in\{0,1\}$ for each $(r,c)\in I^2$. Let
$D_d^- =\{(r,c):r-c=d\}$ and $D_s^+=\{(r,c):r+c=s\}$.
The feasibility model is
\begin{align}
\sum_{c\in I}x_{rc}&=1 &&\forall r\in I,\\
\sum_{r\in I}x_{rc}&=1 &&\forall c\in I,\\
\sum_{(r,c)\in D_d^-}x_{rc}&\le1 &&\forall d:|D_d^-|\ge2,\\
\sum_{(r,c)\in D_s^+}x_{rc}&\le1 &&\forall s:|D_s^+|\ge2.
\end{align}
The constant objective is zero. For $n\ge2$ there are $n^2$ binary variables
and $6n-6$ linear constraints. Singleton diagonals need no constraint.
Gurobi~\cite{gurobi} and CPLEX MIP~\cite{cplex} receive the identical model, with one thread, an explicit
seed, and the default presolve settings. No model receives symmetry-breaking
constraints, a warm start, or a precomputed placement.

\section{SAT encoding}
\subsection{Board variables and formulations}
The Boolean variable $x_{rc}$ means that square $(r,c)$ contains a queen and
has DIMACS index $rn+c+1$. For a literal set $X$, define
\begin{equation}
\ALO(X)=\bigvee_{x\in X}x,\qquad
\EO(X)=\ALO(X)\wedge\AMO(X).
\end{equation}
Write $R_r$, $C_c$, and $\mathcal D$ for row, column, and nonsingleton
diagonal literal sets. The minimal formula is
\begin{equation}
F_{\min}=\bigwedge_r\EO(R_r)\ \wedge\
\bigwedge_c\AMO(C_c)\ \wedge\
\bigwedge_{D\in\mathcal D}\AMO(D).
\end{equation}
The extended formula adds column at-least-one clauses:
\begin{equation}
F_{\mathrm{ext}}=F_{\min}\wedge\bigwedge_c\ALO(C_c).
\end{equation}
Both formulas have exactly the same feasible board placements. Every model
of $F_{\min}$ has exactly $n$ queens by row EO. Column AMO distributes these
queens among $n$ columns with no repetition, so every column is occupied.
Diagonal AMO then gives Equations~\eqref{eq:down}--\eqref{eq:up}. Conversely,
every valid placement satisfies all constraints in both formulations, and
the auxiliary variables of each correct AMO encoding can be extended to
satisfy its CNF. The extended formula contains $n$ additional clauses and
no additional variables. Although logically redundant, those clauses may
change propagation and search.

\subsection{Implementation and correctness checks}
The SAT encoder streams clauses into the chosen solver instead of retaining
a second full Python copy of the formula. An export command produces
standard DIMACS CNF for independent use. Decoding inspects only the first
$n^2$ placement variables, so auxiliary assignments cannot create queens.
Every SAT or CP/ILP solution passes a separate checker for length, domain,
column uniqueness, and uniqueness of both diagonal indices.

The semantic test suite enumerates every truth assignment for AMO groups
of size zero through eleven, for both positive and negative literals. It
then enumerates all projected N-queens solutions for $n=1,\ldots,8$ for all
ten SAT configurations. Blocking clauses use only selected board squares,
so distinct auxiliary assignments cannot be counted as distinct placements.
The resulting solution sets are compared with an independent backtracking
implementation, yielding counts $1,0,0,2,10,4,40,92$. Integration checks
also confirm infeasibility at $n=3$ and a valid solution at $n=8$ for every
CP/ILP backend. These tests verify semantic equivalence rather than only
checking that the code runs. A separate unit-propagation test covers every
selected input for group sizes one through 64, with both literal polarities;
it does not invoke a SAT search. The formula-size recurrences above are
also checked against the generated CNF before drawing the size figure.

\section{Computational experiments}
\subsection{Environment and protocol}
All runs were performed on Windows 11 (build 26200), with an AMD Ryzen 7
8845HS processor (16 logical processors), Python 3.14.5, PySAT 1.9.dev2,
Gurobi 13.0.3, CPLEX Python package 22.2.0.1, DOcplex 2.32.264, and OR-Tools
9.15.6755. CPLEX CP uses the CP Optimizer executable from Optimization
Studio 22.2. The saved configuration files record these versions and the
complete command parameters. Gurobi uses a working WLS license; CPLEX MIP
was verified to accept models beyond the community-edition size limit.

Each experiment runs sequentially in fresh child processes, with one
solver thread and three repetitions. CP/ILP runs use seeds one through
three. SAT backends retain their default parameters; their repetitions
primarily measure timing variation and are not different randomized SAT
seeds. Method order is rotated across repetitions. Every run has a hard
ten-second deadline for the child process, including imports, license
acquisition, construction, and solving. Exceeding this budget yields TO;
it never implies infeasibility. The Windows harness also terminates child
CP Optimizer processes on timeout. Recorded timeout duration includes
termination and cleanup; operating-system delays can make this exceed the
requested budget. Such records remain unfinished runs, regardless of the
cleanup duration.

Two timing measures are kept: process time, measured by the parent, and
core time, equal to model construction plus solver execution. Gurobi WLS
startup is recorded separately as setup time; it is included in process
time but excluded from core time. The main comparison uses process time
to reflect the budget actually enforced. Both timings are reported to
avoid attributing all license and import overhead to search performance.
Construction and solve times cannot be recovered when the process is
killed before returning; these fields remain empty rather than fabricated.

For successful configurations, per-size tables show the median of three
process times. A cell TO $(s/3)$ means only $s$ of three runs finished.
Aggregate rankings use PAR-2: a successful run contributes its process
time, and an unfinished or erroneous run contributes twice the ten-second
budget. This prevents fast successful subsets from hiding failures. The
benchmark contains one standard board per size; repetitions are repeated
measurements, not distinct instances or independent evidence of broad
statistical significance.

\subsection{Limitations}
The ten-second deadline measures short-budget behavior, so a TO is not
evidence that a method cannot solve that size with more time. Core times
should not be read as successful runs under a separate ten-second search
budget: all outcomes were determined by the same process deadline. Startup
overhead is material on small boards, especially for CP-SAT imports and
Gurobi WLS acquisition. Hardware power management and background tasks
may introduce timing noise despite sequential execution.

Only unconstrained square boards and default solver settings are studied.
The selected SAT encoding is optimized using the same family later used
for comparison, and the report does not claim an unbiased general ranking
of solver technology. In particular, better CP, ILP, or SAT formulations,
specialized constructions, symmetry breaking, or different parameter
settings could change the ordering. Large-board tests concern finding one
placement, not exhaustive counting. Completion instances would require
additional benchmarks and conclusions.

\section{Conclusion}
The delivered implementation solves standard N-queens through SAT and four
required CP/ILP baselines, exports CNF, independently checks placements,
and reproduces the measured comparisons. The encoding study separates
formula size from observed runtime, while the formulation study isolates
the effect of redundant column clauses. Process and core timings make
startup costs explicit. Complete small-board solution-set tests support
the correctness of all ten SAT configurations, and saved placements permit
independent validation of every successful benchmark run.
